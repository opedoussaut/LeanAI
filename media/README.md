# Cinematic intro

`scene.html` draws the 37-second intro deterministically (`render(t)`); `render.py` renders it frame by frame with Playwright and ffmpeg (`cd media && python3 render.py` → `silent.mp4`). Fonts: Inter (SIL Open Font License), from @fontsource/inter.

`scene-system1-system2.html` is the 58-second Decision Intelligence film (THE QUESTION: R-17 arrives → COMPLEXITY → GROOM → DECIDE → CONFIDENCE GATE → REASON → ACT → THE DECISION: Loop A would overload, the system rebalances → HUMAN ACCOUNTABILITY → MEASURE → LeanAI). `python3 render-system1-system2.py` renders it, synthesises the soundtrack (`sound-system1-system2.py`, numpy/scipy) and writes `LeanAI-cinematic-intro-system1-system2.mp4` plus its poster. Story and MEASURE figures (869.1 kW, −13.1 kW, 38.7 kW, +25.6 kW, burn-in window, recommendation text) come from the simulated R-17 reference run; System 1 confidences are the model's real outputs for R-17.

`scene-cooling-loop-mbse.html` is the 104-second Engineering Intelligence film (what follows the R-17 decision: future load S4 exceeds Loop A → operational options A–C computed and insufficient → engineering question → LeanAI orchestrator → Cameo MBSE agent → cameo-mcp-bridge → CATIA Magic → the native Cameo diagrams, each captioned WHO created it, WHY it exists and what it SHOWS → identical scenarios S1–S4 → v1/v2 comparison → verification 7/8 vs 8/8 → human decision). All numbers come from `src/engineering/evaluate.js` and the diagrams from `evidence/cameo/` at render time. `python3 render-cooling-loop-mbse.py` (serve the repository root on port 8811 first: `python3 -m http.server 8811`) writes `LeanAI-cinematic-cooling-loop-mbse.mp4` and its poster. `capture-engineering.py` captures the Engineering page section by section after a recorded run (`npm start` first).

`scene-linkedin-square.html` is the 65-second square (1080×1080) social cut: the question, lean grooming, System 1 triage, agents and physics, cost, the future load, the MBSE hand-off, the v1/v2 verdict and the human decision. Its figures come from `linkedin-facts.json`, generated by `node media/linkedin-facts.mjs > media/linkedin-facts.json` with the app's own engine and engineering model. `python3 render-linkedin-square.py` (repository root served on port 8811) writes `LeanAI-linkedin-square-65s.mp4` and its poster.
